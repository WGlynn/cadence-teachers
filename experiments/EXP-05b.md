## Pre-registration (written 2026-10-29, before any EXP-05b check or data life)

**In one line: save a learning brain in the middle of its life and load it in a new Python process. Does it then act and learn exactly, bit for bit, as the brain that was never stopped? And does a `copy.deepcopy` fork do the same? Asked on a task where, after every cut, the brain keeps using at least two actions and (except after the last reset) still has moments in which it learns.**

**What a yes allows.** On this machine and environment (CPU, the NumPy loop because numba is not installed, one BLAS thread, Python 3.12.10, NumPy 2.4.2), for these three compositions and this one-stream task: a saved brain is a safe hand-off point. It can be stopped and resumed in a fresh process with nothing lost, even while an action waits for its outcome, and our harnesses can fork twins with `deepcopy` instead of a file round trip. Not covered: moving a checkpoint to another machine, numba's fused settle, multi-threaded BLAS, the torch backend, batched streams. Upstream recorded that "the fused apical path differs at rounding on one machine" (commit `c7ea9b1`), so a cross-machine move is a separate question.

**Why redo it, and why now.**
- EXP-05 (2026-10-23, Cadence 0.85.1 + 41 commits) stopped at its own check k4, before any data. After youth its brains answered every cue with one fixed action. A continuation that repeats one action matches the reference almost by default, so after 6 of its 14 cuts a match would have proved little. Its brains also never woke at the reversal, so the two reversal cuts (A5, A6) never happened. Its one check life was consistent with exact continuation, but a check life is not a reading.
- Eight releases have shipped since then (0.86.0 to 0.91.1). The ones this test actually exercises:
  - 0.90.0 added the apical compartment and its checkpoint format `cadence-checkpoint/5`; 0.91.1 validates apical checkpoints on every load ("Validate original apical checkpoint types and both topology arrays before construction ... Valid checkpoints retain exact continuation", CHANGELOG 0.91.1, the apical validation bullet). The third brain here is apical, so every one of its loads goes through that new code.
  - 0.89.0 turned the recall position term on by default. Read on the three composed brains before registration (pilot seed 0): `recall.position` 32, 33 buckets, one position map each. So all three brains have this state. Whether `save` writes all of it is part of what this test checks.
- Two 0.91.1 changes are context only; this design does not test them:
  - The recall content cache ("Reuse raw recall content products ... Check a bitwise key snapshot before reuse, so runtime retuning, in-place expert edits and checkpoint continuation agree. Bound the cache to one bank and four addresses per head"). I read the code before registration. The cache is only used inside an aroused `live`. Every slot write empties it, and every `live` and `wait` writes a slot (`stream.py:1564-1565`); a full reset empties it too (`stream.py:1035-1036`). The docs say the same: "a slot write or full reset clears it" (`docs/backends.md:197-200`). So the cache is empty at every cut of this design. Even if it were not, a cache hit returns the same product that a miss computes (`stream.py:1337-1349`). So a load that starts the cache empty cannot change a single bit here. P1 records the cache's size at every cut, so the data can confirm it is empty. Nothing in the verdict rests on the cache.
  - The learned code's restore-on-refusal ("Restore the previous code step and phase when an enclosing action, prediction, wait, lesson or feedback operation refuses"). Any refusal in this harness ends the life: in R or R2 it voids the run, in a restore or fork it refutes the arm. So the refusal path is never exercised. The learned code's saved step (`stepping`) is restored on every load, and that path predates 0.91.1.
- What the docs promise (read at `c9c8080`):
  - `docs/start.md:98`: "`save` and `load` keep the brain's full continuation, pending feedback included." This is the general promise. A mismatch is an upstream bug unless it falls under one of the two documented exceptions below.
  - `docs/api.md:162`: `last_arousal` is "`None` after construction, reset or load". `wait` does not set it, so this test compares it only at `live` events (change 1).
  - `last_settlement` (docstring `generic.py:2194-2195`): "Construction, ``reset`` and ``load`` start with None; diagnostics are not checkpointed." So a loaded brain starts this field empty. That cannot cause a false mismatch here. Every recorded `live` and `wait` fills it before the record is taken, and after a `reset` it is None on both sides.

**Changes from EXP-05.** The first three were queued 2026-10-23 (EXPERIMENT-QUEUE.md, EXP-05b, commit `5fe6d9a`). The rest were added in this pre-registration, most of them after the review below.
1. `last_arousal` is recorded and compared only at `live` events (L and E). At `wait` and `reset` events the field is the constant "not compared". The review read the source: `live` rebuilds the snapshot from scratch at every L and E event (`generic.py:3821`), `reset` clears it (`:4491`), and `wait` never touches it. So at a W event the field is only a leftover from the last `live`, which is compared at its own event or lies before the cut.
2. The task is chosen by a behaviour pilot (below).
3. Fresh seeds: brain `9_055_000 + i`, environment `9_055_200 + i`, data lives i = 0, 1, 2, check life i = 99. Pilot seeds `9_056_000 + i` / `9_056_200 + i`, i = 0..3, are never data. No script in `exp/` used 9_055_xxx or 9_056_xxx before this one (`grep -rnE "\b9_?05[5-6]_?[0-9]{3}\b" --include=*.py`, 2026-10-29: no hits outside this script).
4. A third brain: two regions with the apical compartment (`modules=(16, 8), apical=0.25`). The other two are EXP-05's compositions, now with T3's genes.
5. A registered coverage rule replaces EXP-05's "at least 2 distinct actions" (details under Decision rules). It applies at every cut on every life, data lives included, not only on the check life.
6. Per-brain verdicts are registered beside the pooled verdict.
7. The fork arm takes its deepcopies before any save, and the fork-time digests of D and S come from throwaway copies, so neither continuing twin is saved before the end of its life.
8. The harness pins and asserts the task (T3), the Cadence commit (`c9c8080`, clean) and one BLAS thread; the full run refuses a check made with another task or commit.

**Before registration (disclosed; none of it saves, restores, forks or compares).**
- API probe (seed 1, outside every registered range): all three brains compose with `lateral=0.0, arousal=True, memory_choice=True, recall=True`, live 51 moments, save and load on 0.91.1. About 10 / 24 / 16 ms per moment (plain / learned code / apical).
- Behaviour pilot, run twice on the same pilot seeds, the reference life only, in one process: `MODE=pilot` over all four candidate tasks at once (`exp/EXP-05b-pilot.out` / `.json`, 69 s; that file has no version header), then once more after the review with the registered coverage rule added to its readout (`exp/EXP-05b-pilot2.out` / `.json`, 69 s, header: Cadence 0.91.1 `c9c8080` clean, Python 3.12.10, NumPy 2.4.2, threads 1, numba and torch not installed). The two runs agree on all 48 behaviour rows. There was no other pilot invocation. The pilot never saves, restores, forks or compares, so the task choice is blind to the identity outcome. Candidates, all on EXP-05's schedule (300 moments, waits, resets at 100 / 175 / 250, reversal at 200, salience 0.5 on unpaid outcomes):
  - T0, EXP-05's task (paid 1, unpaid 0, founder genes). It fails the same way on 0.91.1. The reversal cuts A5 and A6 never happen, on 12 of 12 lives. After youth the brains are almost never aroused (1 to 3 moments, on 3 of the 12 lives). Only 5 of 12 lives have at least 2 distinct actions after every cut. Covered under the registered rule: 0 of 12.
  - T1, paid +1, unpaid -1, founder genes; T2, the same plus the operating point of the docs' `live` example (`consolidation=0.25, actor_eta=0.1, actor_eta_bias=0.01`, docs/start.md "Routine and repair"). T2 leaves out that example's `arousal_youth=30`, because the cut rules put A1 at moment 40 and A2 at 60..99, inside a 100-moment youth. For the same reason the queue's "longer `arousal_youth`" lever was not piloted. Both learn the map: accuracy over moments 100-199 is 1.00 on 12 of 12 T2 lives and .70 to 1.00 on T1. But no brain wakes at the reversal: 0 aroused moments after youth on 24 of 24 lives. Accuracy over moments 200-299 is 0.00 on 12 of 12 T2 lives and 0.00 to .26 on T1. A5 and A6 never happen. Covered: 0 of 12 each.
  - T3, T2 plus `arousal_need=0.5` (half the paid reward; one value, not swept). All 9 cut types on 12 of 12 lives. Every cut covered under the registered rule on 12 of 12 (the smallest second-action share after any cut is .26). 39 or 40 aroused moments in 200-249 on every life. Accuracy 100-199 1.00 on every life, 200-299 .56 to .78. The only cut never followed by an aroused moment is B3 (the `reset(keep=("slots",))` at 250): on every pilot life the brain stays calm for its last 50 moments.
  - **T3 is chosen** by the rule written in the queue before the pilot ("every cut type is followed by at least 2 distinct actions and the reversal wakes the brain (A5/A6 occur)", committed `5fe6d9a`, 2026-10-23). It was the only candidate that met it, and it is also the only one that meets the stricter registered coverage rule.
- Side observation (pilot T2, plain brain, life 0, one life, read from `last_arousal` after the pilot, verified twice). At the reversal, surprise is positive at 16 moments from 202 to 246, peaking at .55 (moment 208). The level peaks at .13 (moment 215), below the 0.2 threshold. Want is exactly 0 at all 100 punished moments. The error reaches 2.49, and the reward scale is 0 at the end. This is what the documented law predicts, whatever the sign of the reward. The `reset(keep=("slots",))` at moment 100 cleared the scale, a calm brain learns no outcome so the scale stays empty, and a want term with a zero denominator is zero. The docs say it in their own words: "an adult at `need=0` is roused only by surprise and can stay calm in a world that stopped paying" (`docs/start.md:564-567`). The `reset` docstring at `generic.py:4462-4463` adds that it "may leave it calm on a lapsed habit". Only one part is open: whether surprise alone can ever reach the threshold on such a brain. Not part of this experiment's question; queued as EXP-05c (low priority), no claim.

**Drafts.** The lab's automatic checkpoint committed two earlier drafts of this file and the harness, at `91c3881` (10:47) and `2fc0d39` (10:58). Both were before the review and before any check or data life. The registered version is the commit titled "EXP-05b pre-registered".

**Review before registration (2026-10-29).** Three independent reviewers read this draft and the harness against the 0.91.1 source, each from one angle: harness bugs, unsaved library state, and design. They ran only probes on outside seeds, with no restore-versus-reference comparison on registered seeds. Findings and what changed:
- Harness: the task was not pinned. A full run started without `TASK` would have run EXP-05's collapsing task and pooled it with a T3 check life into a false CONFIRMED. Now asserted, recorded and cross-checked (change 8).
- Source: no load-bearing unsaved state was found. A save and load leaves documented diagnostics, scratch values overwritten before use, graph caches rebuilt on first use, and type-only differences; every random generator, counter, eligibility trace and episodic path was restored. The cache premise of the draft was wrong and is now context only (above).
- Design: the weak 2-action guard, the k5 contradiction (the draft both stopped and shortened the run on k5), pooled-only verdicts, the side observation's numbers and its docs quote, the unscoped "what a yes allows", a k3 that a raising restore could pass, and the cost figure. All are fixed below.

**Setup (pinned).**
- Cadence main `c9c8080` (`__version__` 0.91.1), editable install, clean. Python 3.12.10, NumPy 2.4.2, numba and torch not installed, `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS` = 1 in every process. The harness prints all of these and refuses to run otherwise.
- Three brains, each `Brain.compose(6, 3, seed=s, lateral=0.0, arousal=True, memory_choice=True, recall=True, consolidation=0.25, actor_eta=0.1, actor_eta_bias=0.01, arousal_need=0.5, ...)` with: plain `modules=(16,)`; code `modules=(16,), learned_code=16`; apical `modules=(16, 8), apical=0.25`. Every other gene is the library default; the check prints `describe()["genes"]` and `describe()["layout"]["composition"]` for each.
- Task T3, otherwise EXP-05's schedule exactly. 6 inputs (cues 0..3 one-hot, a wait frame at index 4, an end frame at index 5), 3 actions, 300 moments, the cue at each moment drawn once from the environment seed. The paying action for cue c is `c % 3` before moment 200 and `(c + 1) % 3` from moment 200. The outcome of the action issued at moment m is reported at the next `live`: reward +1.0 if it paid, else -1.0 with `salience=[0.5]`, always with `decision_id` set to the id read when the action was issued. After the `live` of moment m, 0, 1 or 2 wait frames (probabilities .7 / .2 / .1, from the environment seed) are sensed with `wait`. Episodes end at moments 100, 175 and 250: the pending outcome is reported on the end frame with `done=[True]`, the action that call issues is dropped, the brain is reset (`reset(keep=("slots",))` at 100 and 250, the default `reset()` at 175, which keeps the arousal), and moment m starts with `live(cue)` and no reward. The life ends right after the `live` of moment 299, with an action pending.
- Trace: every event records exactly the returned action, `decision_id`, `pending_feedback`, `last_settlement` (every field) and, at L and E events only, `last_arousal` (every field); floats as `float.hex`. Final digest: SHA-256 of the checkpoint bytes, plus a member digest (name, dtype, shape, data) to tell an encoding difference from a state difference.
- Cuts, chosen by rule from the reference trace before any restore: A1 the `live` of moment 40 (youth, sampled action pending); A2 the first `wait` at 60..99; A3 the first routine `live` at 130..174; A4 the first `wait` at 130..174 under a routine action; A5 the first aroused `live` at 200..249; A6 the first `wait` at 200..249 under an aroused action; B1 / B2 / B3 right after the resets at 100 / 175 / 250.
- Processes, each a fresh `python` with its own `PYTHONHASHSEED`, at most 4 at once: R and R2 (the uninterrupted life twice, hash seeds 1 and 2); P1 (the life saving at every cut and living on, the A0 reading; it also records the recall cache's size at each cut); P2 per cut (load in a fresh process, continue every remaining event with the same inputs, save at the end; a separate load saved at once gives the round trip); F per cut (live to the cut, take D = deepcopy and X = deepcopy before any save, then save O and load S from it; X sees cue `(c + 1) % 4` and is paid for its own actions; O, D, S, X run interleaved to the end).

**Check (`MODE=check TASK=T3`, life 99, all three brains, before the data lives). A failure of any of k1 to k5 stops the run, and the experiment is VOID.**
- (k1) All 9 cut types are available on each brain, and each cut saved the groups its type requires (EXP-05's table: A1 / A5 `pending/` and `lived` sampled; A3 `lived` not sampled, no `pending/`; A2 / A4 / A6 also `awaiting`; B1..B3 none of them).
- (k2) R and R2 agree exactly (trace and final bytes).
- (k3) Sensitivity, at the first available of A3, A1: the unperturbed restore at that cut equals R, and a second restore that adds 1e-9 to the first reward it reports raises nothing and differs from R in both its trace and its final checkpoint bytes. Also, the member digest moves when one float in a copy of a cut checkpoint moves by one ULP.
- (k4) Every cut's checkpoint bytes differ from the final bytes, and every cut is covered (rule below).
- (k5) The projected full run (check wall time x 3) is at most 15 minutes.
- Identity comparisons on the check life are printed with the check and count in the verdict, flagged as the check life. Only k1 to k5 stop the run.

**Decision rules (written before any check or data).**
- Coverage of a cut on a life. Count, in the reference's events after the cut, the `live` moments only (L events; the action an end frame returns is dropped by the environment). The cut is covered if at least 2 actions are each taken at no less than 10% of those moments, and at least one of them is aroused, except after B3, whose continuation is routine by design. An uncovered cut is still compared, and a difference there refutes like any other. But a match there does not count toward CONFIRMED.
- VOID (whole experiment): any of k1 to k5 fails (no data run); R differs from R2 on any data life; R or R2 raises; or a role process dies (nonzero exit with no recorded exception) twice in a row. A role process that dies once is rerun once, and the rerun is recorded.
- Arm A, cuts A1..A6. CONFIRMED: A0 holds on every life (P1 equals R in trace and final bytes, and P1 raises nothing); at every A cut on every life (3 data lives and the check life, 3 brains), P2's continuation equals R event for event and its final checkpoint has R's bytes; and on every brain every A cut type is covered on at least one life. REFUTED: any difference at any A cut, covered or not; a load, save or continuing call that raises; or A0 failing. INCONCLUSIVE: nothing refuted, but some A cut type is not covered on any life of some brain (named).
- Arm B, cuts B1..B3: the same rules without A0 (A0 belongs to arm A only). B3 tests the routine path only; arm B's coverage of the learning path rests on B1 and B2.
- Arm C, every cut. CONFIRMED: at every cut on every life, O, D and S each equal R after the cut and end on R's bytes; the fork-time checkpoints of O, D and S have the same bytes; X differs from R everywhere; and on every brain every cut type is covered on at least one life. REFUTED: any of O, D, S differs (naming which: deepcopy, save/load, or the original beside them), or a deepcopy, save, load or continuing call raises. INCONCLUSIVE: nothing refuted, but X equals R somewhere or a coverage gap (named).
- Per-brain verdicts: each arm is also judged on each brain alone (plain, code, apical) by the same rules and reported beside the pooled verdict. The overall label uses the pooled arms; a per-brain split is reported as registered here, not as a new claim.
- A mismatch is followed to its first differing event and, at the end, to the checkpoint members that differ; the member digest says whether bytes differ with equal members (encoding) or the members differ (state).
- Overall: all three arms CONFIRMED -> SUPPORTIVE (loop CONFIRMED). Any arm REFUTED -> BOUNDARY if another arm is CONFIRMED, NULL if none is (loop REFUTED either way). No arm refuted but one INCONCLUSIVE -> SUPPORTIVE with the gap named (loop INCONCLUSIVE).
- A refutation where the docs promise an exact continuation gets a minimal reproduction for Will at `Desktop/Cadence/cadence-pr-draft-2026-10-29-snapshot-<slug>.md`; nothing is filed or posted.
